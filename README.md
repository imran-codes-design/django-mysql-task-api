# 🚀 Django MySQL Task Management REST API

A full-stack backend project built with **Django, Django REST Framework, and MySQL**.

This project demonstrates how to integrate a relational database with a Django backend and expose database operations through a RESTful API.

It was developed as part of a **Full Stack Development – Database Integration** project.

---

# 📌 Project Overview

This project implements a **Task Management REST API** where users can create, read, update, and delete tasks.

The backend uses:

- Django
- Django REST Framework
- MySQL
- Django ORM
- REST API
- Git & GitHub

The project demonstrates the complete flow:

    Client
       ↓
    REST API
       ↓
    Django
       ↓
    Django ORM
       ↓
    MySQL Database

# 🗄️ Database Design

The project uses a MySQL relational database.

The main model is:

    User
      │
      │ 1
      │
      │
      │ M
      ↓
    Task

One user can have multiple tasks.

This represents a:

    One-to-Many (1:M)

relationship.

---

# 📋 Task Model

The Task model contains:

| Field | Type | Description |
|------|------|-------------|
| id | Integer | Primary key |
| user | Foreign Key | Task owner |
| title | String | Task title |
| description | Text | Task description |
| completed | Boolean | Task completion status |
| created_at | DateTime | Task creation time |

The `id` field is automatically generated by Django as the primary key.

The `user` field creates a foreign-key relationship with Django's User model.

---

# 🔐 Database Constraints

The project demonstrates database constraints including:

### Primary Key

Every task has a unique `id`.

### Foreign Key

Each task is connected to a user.

### NOT NULL

Required model fields cannot contain NULL values unless explicitly configured otherwise.

### CHECK Constraint

The task title cannot be an empty string.

These constraints help maintain data integrity.

# 🔄 CRUD Operations

The REST API supports all major CRUD operations.

CRUD means:

    Create
    Read
    Update
    Delete

The API maps these operations to HTTP methods:

| HTTP Method | Operation | Database Action |
|-------------|-----------|-----------------|
| POST | Create | INSERT |
| GET | Read | SELECT |
| PUT | Update | UPDATE |
| PATCH | Partial Update | UPDATE |
| DELETE | Delete | DELETE |

# 🌐 API Endpoints

## Get All Tasks

    GET /api/tasks/

Returns all tasks.

Example:

    http://127.0.0.1:8000/api/tasks/

---

## Create a Task

    }

    GET /api/tasks/<id>/

Example:

---

## Update a Task

    PUT /api/tasks/<id>/

Example:

    {

        "description": "Complete the API project",
        "completed": true

## Partially Update a Task

---

## Delete a Task

# 🔧 Django REST Framework

Django REST Framework is used to convert database objects into JSON and handle API requests.

The project uses a `ModelSerializer`.

The serializer converts:

    Django Model
          ↓
       JSON

and also converts:

    JSON
      ↓
    Django Model

This makes communication between the API and client applications easier.

---

# 🧩 API Views

The project uses Django REST Framework generic class-based views.

For collection operations:

    ListCreateAPIView

This handles:

    GET
    POST

For individual objects:

    RetrieveUpdateDestroyAPIView

This handles:

    GET
    PUT
    PATCH
    DELETE

This reduces repeated code and provides a clean CRUD implementation.

---

# 🗃️ Django ORM

The project uses Django ORM instead of writing SQL manually for normal database operations.

For example:

    Task.objects.all()

retrieves tasks from the database.

Creating a task can be handled through the serializer and Django ORM.

Updating and deleting objects are also handled through Django ORM.

The ORM converts Django operations into SQL queries that are executed against MySQL.

---

# 🐬 MySQL Integration

The project uses MySQL as the relational database.

The database configuration is defined in:

    config/settings.py

Example:

    DATABASES = {
        "default": {
            "ENGINE": "django.db.backends.mysql",
            "NAME": "project3_db",
            "USER": "root",
            "PASSWORD": "YOUR_MYSQL_PASSWORD",
            "HOST": "127.0.0.1",
            "PORT": "3307",
        }
    }

Replace the database credentials with your own MySQL configuration.

# ⚙️ Installation

## 1. Clone the Repository

    git clone https://github.com/imran-codes-design/django-mysql-task-api.git

Enter the project directory:

    cd django-mysql-task-api

---

# 2. Create a Virtual Environment

Windows:

    python -m venv venv

Activate it:

    .\venv\Scripts\Activate.ps1

---

# 3. Install Dependencies

    pip install -r requirements.txt

---

# 4. Create MySQL Database

Open MySQL and create a database:

    CREATE DATABASE project3_db;

You can use a different database name if required.

---

# 5. Configure Database

Open:

    config/settings.py

Update:

    NAME
    USER
    PASSWORD
    HOST
    PORT

according to your MySQL configuration.

---

# 6. Run Migrations

Run:

    python manage.py makemigrations

Then:

    python manage.py migrate

Django will create the required database tables.

---

# 7. Create Superuser

Create an admin account:

    python manage.py createsuperuser

Follow the instructions in the terminal.

---

# 8. Start the Development Server

    python manage.py runserver

The server will start at:

    http://127.0.0.1:8000/

# 💾 Data Persistence

One important purpose of database integration is persistent storage.

Data is not simply stored temporarily in application memory.

When a task is created:

    API
     ↓
    Django
     ↓
    MySQL

The task remains stored in MySQL until it is updated or deleted.

This allows the application to maintain data between server restarts.

# 🔐 Security Considerations

The project uses Django ORM for database operations.

Using ORM-based queries helps avoid manually constructing unsafe SQL queries in normal application operations.

For production applications, additional security should be implemented, including:

- Environment variables for database credentials
- Authentication
- Authorization
- HTTPS
- Input validation
- CORS configuration
- Rate limiting
- Secure production settings
- Proper secret-key management

Never commit real passwords or secret keys to a public GitHub repository.

# 🚀 How You Can Use This Project in Your Own Projects

This project can be used as a reusable backend foundation for your own database-driven applications.

You do not need to build the complete Django setup, MySQL integration, REST API structure, serializers, views, and CRUD logic from scratch.

You can clone this project, modify the models, and build your own application on top of it.

---

# 1. Clone the Project

Start by cloning the repository:

    git clone https://github.com/imran-codes-design/django-mysql-task-api.git

Then enter the project:

    cd django-mysql-task-api

Install the dependencies:

    pip install -r requirements.txt

---

# 2. Connect Your Own MySQL Database

Create a new MySQL database for your application.

For example:

    CREATE DATABASE my_project_db;

Then update:

    config/settings.py

Replace the existing database name and credentials with your own.

The current project contains a `Task` model.

You can modify the existing model or create completely new models according to your project requirements.

# 4. Create Your Database Tables

After changing or creating models, run:

    python manage.py makemigrations

Then:

    python manage.py migrate

Django will create or update the corresponding MySQL database tables.

---

# 5. Create Serializers

Create serializers for your new models.

Serializers allow your Django models to communicate through the REST API using JSON.

For example:

    class ProductSerializer(serializers.ModelSerializer):
        class Meta:
            model = Product
            fields = "__all__"

---

# 6. Create API Views

Create API views for your new application.

You can reuse the CRUD pattern from this project.

For example:

    GET     → Retrieve data
    POST    → Create data
    PUT     → Update data
    PATCH   → Partially update data
    DELETE  → Delete data

This allows you to quickly create REST APIs for your own database models.
